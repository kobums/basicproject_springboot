# basicproject_springboot

gomachine 용 Spring Boot 시작 프로젝트. 템플릿에는 인증(회원가입 / 로그인 / 내 정보), JWT, 업로드, 보안 설정만 있고
테이블 CRUD(엔티티 / 리포지토리 / 서비스 / 컨트롤러)는 모두 gomachine 이 `model.json` 과 DB 스키마로 만든다.
표준 스키마(`user`, `board`)의 생성 코드는 커밋되어 있어서 받자마자 빌드된다.

## 기술 스택

- Spring Boot 4.1.2 (Spring Framework 7, Spring Security 7, Hibernate 7, Jackson 3)
- Kotlin 2.3.21 (Boot 가 관리하는 버전, `spring` / `jpa` 플러그인), Java 21
- Gradle 9.8.2 (wrapper)
- JJWT 0.13 (HS256), bcrypt
- MariaDB 11.4 (docker compose), 테스트는 H2 (MariaDB 모드)

## 빠른 시작

```bash
cp .env.example .env            # 값 바꾸기 (특히 JWT_SECRET, 32 바이트 이상)
docker compose up -d db         # MariaDB + db/schema.sql (처음 뜰 때 한 번)
buildtool-model .               # (선택) 생성 코드 다시 만들기, ./gradlew gen 과 같다
./gradlew bootRun               # http://localhost:8081
```

- `./gradlew bootRun` 과 `./gradlew gen` 은 `.env` 를 읽어 환경변수로 넣는다 (이미 설정된 환경변수가 우선).
- `./gradlew gen` 은 PATH 의 `buildtool-model` 을 부른다 (gomachine `make install`). DB 가 떠 있어야 한다.
- `./gradlew build` 는 DB 없이 된다 (테스트는 H2 에 `db/schema.sql` 을 올려서 돈다).
- 서버까지 docker 로 띄우려면 `docker compose --profile api up -d --build` (Dockerfile, JRE 21).

## 구조

```
model.json                      gomachine 설정 (spring, kotlinPackage, auth jwt, 테이블 설정)
db/schema.sql                   표준 스키마 (gomachine bootstrap 과 같다)
docker-compose.yml, .env.example
src/main/kotlin/com/basicproject/api
├── BasicprojectApiApplication.kt
├── auth/        회원가입 / 로그인 / 내 정보 (손으로 만든 코드)
├── security/    JWT 발급·검증, 필터, SecurityConfig, PasswordEncoder 빈
├── upload/      이미지 업로드, /uploads 정적 서빙
├── common/      auth / upload 의 에러 응답
├── config/
│   ├── SessionProvider.kt          gomachine 이 없을 때만 만든다 (사용자 파일)
│   └── SecuritySessionProvider.kt  SessionProvider 구현 (SecurityContext → 로그인 사용자)
├── entity/ repository/ service/ controller/   gomachine 생성 (첫 줄 "// Code generated by gomachine. DO NOT EDIT.")
└── support/DateParams.kt                       gomachine 생성
```

- 생성 파일은 고치지 않는다. 다시 만들면 덮어쓴다. 바꿀 것은 `model.json` / 스키마로 바꾸거나 다른 파일에 둔다.
- 첫 줄에 생성 머리줄이 없는 파일은 gomachine 이 덮어쓰지 않는다. 그래서 손으로 만든 코드는 생성 클래스와 이름이 겹치지 않게 둔다
  (`User`, `UserRepository`, `UserService`, `UserController` 같은 이름은 생성 코드가 쓴다).

## 테이블 추가

1. `db/schema.sql` 에 테이블을 추가하고 DB 에 적용한다 (`{name}_tb`, 컬럼 `{접두사}_{이름}`, 생성 시각은 `{접두사}_createddate`).
   `db/schema.sql` 은 볼륨이 비어 있을 때만 실행되므로, 이미 떠 있는 DB 에는 새 `CREATE TABLE` 문을 직접 실행한다
   (데이터를 지워도 되면 `docker compose down -v && docker compose up -d db`).
2. 필요하면 `model.json` 의 `table` 에 설정을 넣는다 (`session`: 소유자 컬럼, `protect`: 클라이언트가 못 바꾸는 컬럼, `join` 등).
3. `buildtool-model .` (또는 `./gradlew gen`) → `entity/`, `repository/`, `service/`, `controller/` 에 `{Model}*.kt` 가 생긴다.
4. `./gradlew bootRun`. 경로는 `/api/{table}` (목록 / 개수 / 단건 / 검색 / 생성 / batch / 수정 / 삭제).

생성 API 의 규칙(필터, 페이지, 정렬, 응답 모양, 소유권)은 gomachine README 의 "Spring (Kotlin)" / "HTTP 계약" 절을 본다.

## 인증

| Method | Path | 설명 | 로그인 |
|---|---|---|---|
| POST | `/api/auth/signup` | 회원가입 (`{email, password, name}`, level 1) 후 토큰 발급, 201 | X |
| POST | `/api/auth/login` | 로그인 (`{email, password}`) 후 토큰 발급 | X |
| GET | `/api/auth/me` | 현재 토큰의 사용자 | O |
| POST | `/api/upload` | 이미지 업로드 (multipart, 필드 이름 = form 값 `name`, 기본 `upload`) | O |
| GET | `/uploads/{filename}` | 업로드 파일 | X |
| * | `/api/{table}/...` | gomachine 생성 API | 컨트롤러가 확인 |

- 로그인 / 회원가입 응답: `{"token", "tokenType": "Bearer", "expiresInMs", "user": {id, email, name, level, createddate}}` (Go 템플릿과 같다).
- 잘못된 이메일 / 비밀번호는 같은 메시지로 400, 이미 있는 이메일은 400, 형식 오류는 400 + `fieldErrors`.
- 업로드 응답: `{"filename": "20260102/abc....png", "original", "url": "/uploads/20260102/abc....png"}`.
  jpg / jpeg / png / gif / webp 만 받는다 (확장자 + 파일 시그니처 검사, 5MB). `filename` 을 컬럼(예: `board.img`)에 저장한다.
- 생성 API: Spring Security 는 `/api/**` 를 막지 않고, 생성 컨트롤러가 `SessionProvider.currentUserId()` 로 직접 401 을 돌려준다.
  `POST /api/user` (생성 API 의 회원가입) 만 로그인 없이 된다 (Go 와 같다). 이 경로로 만든 회원은 `level` 이 0 이다 (보호 컬럼).
  `board` 는 `model.json` `session` 설정으로 작성자(`user`)가 로그인 사용자로 정해지고, 목록 / 수정 / 삭제가 본인 글로 제한된다.
- 비밀번호는 bcrypt (`PasswordEncoder` 빈 하나를 인증과 생성된 `UserService` 가 같이 쓴다).

### 통일 JWT (Go / Spring / Rust 공통)

```
Authorization: Bearer <token>
```

```json
{ "sub": "42", "id": 42, "email": "a@b.c", "level": 1, "iat": 1767225600, "exp": 1767312000 }
```

- HS256 고정, 키는 `JWT_SECRET` 의 UTF-8 바이트 (32 바이트 이상, 없거나 짧으면 서버가 시작하지 않는다).
- `iat` / `exp` 는 초 단위 정수, 유효 시간은 기본 24시간 (`JWT_EXPIRATION_MS`).
- 읽을 때: `id` 가 없으면 `sub` 를 숫자로 읽고, `level` 은 없으면 0, `exp` 는 있으면 검증한다.
- 같은 `JWT_SECRET` 을 쓰는 basicproject_go / Rust 백엔드가 발급한 토큰을 그대로 받는다.
- 토큰이 잘못되면(형식, 서명, 만료, HS256 이 아닌 알고리즘) 비로그인으로 처리한다 → 로그인이 필요한 곳은 401 (500 이 아니다).
  잘못된 토큰이 붙어 있어도 로그인 / 회원가입은 된다.

## 환경변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `8081` | 서버 포트 |
| `DB_HOST` / `DB_PORT` | `127.0.0.1` / `3306` | MariaDB |
| `DB_NAME` | `MARIADB_DATABASE`, 없으면 `project` | DB 이름 |
| `DB_USER` / `DB_PASSWORD` | `project` / 없음 | DB 계정 (gomachine 도 같은 값을 쓴다) |
| `DB_URL` | - | 있으면 위 값 대신 쓰는 JDBC URL |
| `JWT_SECRET` | 없음 (필수) | HS256 키, 32 바이트 이상 |
| `JWT_EXPIRATION_MS` | `86400000` | 토큰 유효 시간 |
| `CORS_ORIGINS` | `http://localhost:*,http://127.0.0.1:*` | 허용 origin 패턴 (쉼표 구분) |
| `UPLOAD_DIR` | `uploads` | 업로드 저장 디렉터리 |
| `MARIADB_*` | - | docker compose db 서비스 |

## 포트

- Spring 서버 `8081` (basicproject_vue 의 vite 프록시가 8081 로 보낸다).
- MariaDB `3306` (`DB_PORT`). gomachine 은 아직 3306 으로만 접속한다.

## 설정 메모

- `spring.jpa.hibernate.naming.physical-strategy=PhysicalNamingStrategyStandardImpl`: 생성 엔티티의 `@Column(name)` 을 그대로 쓴다.
- `ddl-auto: none`: 스키마는 `db/schema.sql` 이 관리한다.
- `open-in-view: false`, `show-sql: false`.
- CORS 는 `/api/**`, `/uploads/**` 에 `GET/POST/PUT/PATCH/DELETE`, `Authorization` 헤더를 허용한다.

## 빌드 / 테스트

```bash
./gradlew build     # 컴파일 + 테스트 (DB 필요 없음)
./gradlew test
```

테스트(`src/test/kotlin`): 회원가입 → 로그인 → 토큰 형식, 생성 `POST /api/board` 의 작성자 = 로그인 사용자, 다른 사용자 목록 분리,
토큰 없음 / 잘못된 토큰 401, Go 형식 토큰 수락, 생성 `POST /api/user` 와 로그인 해시 호환, 업로드, CORS preflight.
